Namespace Cad2Gdml.Meshes (C# 7.3, net48, no packages). Create `public static class HoleFiller` with ONE public method:
`public static Mesh Fill(Mesh welded, int maxLoopEdges, out int filled, out int skipped)`.
Input: a welded indexed mesh (Mesh.Vertices list of Vec3d, Mesh.Indices list of int, three per triangle; check Mesh.cs for the exact members and for how to build a new Mesh by adding to Vertices/Indices). Output: a NEW mesh (the input is never modified) that contains all original triangles plus cap triangles closing the boundary loops; returns null when no loop was filled. `filled` = number of loops closed, `skipped` = number of loops left open.
Algorithm: (1) count each undirected edge; a boundary edge is an edge used by exactly one triangle; remember its direction (a -> b as it occurs in that triangle). Edges used by 3+ triangles are ignored. (2) Build for every boundary vertex the list of outgoing boundary edges keyed by the START vertex of the REVERSED direction, i.e. a cap triangle must use the edge as b -> a. Chain boundary edges into loops: start from the smallest unused boundary edge (ordered by (a,b)), repeatedly follow from vertex b to the unused boundary edge whose start is b... (the boundary edges of one hole, taken with their original direction a -> b, form a directed cycle a -> b -> c -> ... because the hole is lined with triangles all traversing the border the same way around); stop when the start vertex is reached again. A loop is valid only when it closes, has no repeated vertex and has between 3 and maxLoopEdges edges; otherwise count it in `skipped` and mark its edges used. A vertex with more than one unused outgoing boundary edge makes the loops containing it ambiguous: take the smallest end vertex first; loops that fail to close are skipped. (3) For a valid loop v0 -> v1 -> ... -> vk-1 -> v0 (original direction) add the cap with REVERSED orientation: for a loop of 3 vertices one triangle (v0, v2, v1); for longer loops add a new vertex at the centroid c of the loop vertices and the triangles (c, v(i+1), v(i)) for every edge i -> i+1 (including the closing edge). New vertices are appended to the end of the vertex list; the order of everything must be deterministic (no Dictionary enumeration order dependence: iterate sorted keys).
