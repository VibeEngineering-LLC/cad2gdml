# cad2gdml

Конвертер CAD/сеток (STL, 3MF, OBJ, STEP, Blender) в GDML для Geant4 и BecqMoni: пишет `output.gdml`, эскиз сечения `output.png` и описание `output.report.txt`.
Лицензия MIT. Статус: тестовая сборка v0.8, в Geant4 полученный GDML ещё не загружался.

## Запуск

Окно: `Cad2GdmlApp.exe`. Добавьте файлы или папку, выберите единицы входа (для STL/OBJ обязательно), при необходимости укажите кристалл и фронт, нажмите «Конвертировать».
Кнопка «Сцена и вещества…» открывает трёхмерный просмотр: вращение мышью, сечение по оси, включение/выключение деталей галочкой, вещества по-русски. Выбранная деталь подсвечивается.

Командная строка:

```
cad2gdml <файл|папка>... --out <папка> [--name имя] [--unit mm|cm|m|inch]
         [--crystal имя] [--front +z|-z|+x|-x|+y|-y|auto] [--materials файл.json]
         [--material имя=вещество] [--density вещество=г/см3] [--role имя=роль]
         [--allow-default-material] [--keep-open | --drop-open] [--no-split] [--no-repair] [--weld мм]
```

Коды выхода: 0 готово; 2 вход/единицы/формат/STEP; 3 сетка; 4 роли/кадр; 5 вещество; 9 внутренняя ошибка.

Переменные окружения: `CAD2GDML_VERBOSE=1` (показать служебные сообщения), `CAD2GDML_TRACE=1` (метки этапов), `CAD2GDML_PYTHON`, `CAD2GDML_STEP_SCRIPT` (модуль STEP), `CAD2GDML_BLENDER`, `CAD2GDML_BLEND_SCRIPT` (вход `.blend`).

`--front`: буква — ось кристалла в системе файла, знак — передний торец; `auto` — ось по тензору инерции, торец по центру масс остальных деталей. В окне то же поле «Ось/фронт».

## Подготовка модели

Качество GDML определяется исходником, а не конвертером. Что нужно:

- **Формат с именами деталей:** OBJ (экспорт «по объектам», с материалами), 3MF, STEP или `.blend`. **STL — один слитый набор треугольников без имён и материалов:** детали, сшитые общими вершинами (резиновые вставки, запрессованные в корпус), в STL разделить нельзя — конвертер честно оставляет их одним телом. Для многодетальных сборок STL не подходит.
- **Одна деталь = одно замкнутое тело.** Не объединяйте разные вещества в один объект; не оставляйте дыр, двойных стенок, перекрытий между деталями (пересечения конвертер не проверяет).
- **Полое тело (отражатель с полостью) — стенка должна иметь толщину:** внутренняя оболочка не должна касаться внешней ни рёбрами, ни вершинами. Касание по ребру даёт неманифольдную сетку (ребро у 4 граней) и предупреждение Geant4 «wrong orientation».
- **Без микро-граней:** треугольники нулевой площади и T-стыки (вершина на середине чужого ребра) создают дыры при записи в Geant4; перед экспортом объединяйте близкие вершины (Merge by Distance ~1e-4 мм) и закрывайте поверхность. Конвертер убирает такие грани сам, но не всегда.
- **Имена деталей — по веществу или назначению:** `Crystal_LaBr3`, `Housing_Al6063`, `Reflector_PTFE`, `Bezel_PC`, `Rubber_seal`, `Board_FR4`, `Source_water` — по ним назначаются вещества и роли. Иначе положите рядом `materials.json` или задайте вещества в окне «Сцена и вещества» (там же — плотность; её можно изменить, по умолчанию берётся из справочника).
- **Материалы в CAD/Blender:** назначьте каждому объекту материал с понятным именем (`Aluminium`, `LaBr3`, `Teflon`) — для OBJ и `.blend` он читается из `usemtl`, когда имя детали ничего не говорит.
- **Детализация:** кристалл, отражатель, окно, корпус, защита, образец — обязательно; винты, резьбы, фаски, надписи — лишние (тысячи треугольников без влияния на отклик). Разумный размер: до ~100 тыс. треугольников на сцену.
- **Единицы и ориентация:** STEP и `.blend` — в миллиметрах из файла; для STL/OBJ единицы задаются при конвертации. Ось кристалла и передний торец определяются автоматически; если модель повёрнута иначе — задайте `--front`/«Ось/фронт».

## Blender

Файл `.blend` читается самим Blender (нужна установка, `blender.exe` ищется в `Program Files\Blender Foundation` или через `CAD2GDML_BLENDER`): видимые mesh-объекты экспортируются в мировых координатах, имя объекта становится именем детали, материал — `usemtl`. Скрытые объекты и не-mesh пропускаются.

## Что делает

Сшивает сетки, делит слитые файлы на тела, заделывает дыры (крышки и корпус остаются в сцене), находит кристалл и образец, ставит ось кристалла на z, распознаёт цилиндры, трубы, ступенчатые тела вращения и параллелепипеды, остальное пишет как `tessellated`, назначает вещества по именам и вручную.

Вещества: если рядом с моделью лежит `materials.json` (или `<имя>.materials.json`), он подхватывается сам. Для OBJ учитывается имя материала `usemtl`, когда по имени детали вещество не определилось. Роли (`Crystal`, `Source`, `Container`, `Shield`, `Housing`, `Other`) можно задать в окне «Сцена и вещества» или ключом `--role`.

## STEP

Для STEP открытые детали, которые не удалось закрыть, по умолчанию остаются в сцене (как `--keep-open`, в отчёте стоит предупреждение). Чтобы исключить их, используйте `--drop-open` или галочку «Пропускать открытые детали».

Читается внешним процессом Python 3.12 с OpenCASCADE (`cadquery-ocp-novtk` 8.0.1.1.0). Модуль поставляется отдельным архивом со своим Python: распакуйте его так, чтобы каталог `tools` лежал рядом с `cad2gdml.exe`; ставить Python не нужно (можно задать свой через `CAD2GDML_PYTHON`, версия 3.12).

## Ограничения

- Пересечения деталей не проверяются.
- STL: детали, сшитые общими вершинами, не разделяются (ограничение формата, см. «Подготовка модели»).
- Открытые сетки закрываются автоматически; если не вышло, деталь остаётся открытой и в отчёте стоит предупреждение.
- Эскиз — сечение плоскостью y=0 (вид x–z).
- Нативный код OpenCASCADE антивирусом проверен, анализом кода — нет.

## Сборка

```
dotnet build src/Cad2Gdml.Cli -c Release
dotnet build src/Cad2Gdml.App -c Release
dotnet build src/Cad2Gdml.Tests -c Release -o work/bin/tests && work/bin/tests/Cad2GdmlTests.exe
```

Нужны .NET SDK и .NET Framework 4.8.
