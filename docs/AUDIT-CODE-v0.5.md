## Находки

### B1. Блокер. Тела с общей гранью одинакового контура рассыпаются на куски, часть треугольников теряется, конвертация падает; обхода нет

Файл:строка: `src/Cad2Gdml.Core/Meshes/ComponentSplitter.cs:52` (склейка только по рёбрам с ровно двумя гранями), `src/Cad2Gdml.Core/Pipeline/Cad2GdmlPipeline.cs:382` (куски менее 4 треугольников удаляются), `Cad2GdmlPipeline.cs:284` (при `--no-split` неманифольдное ребро становится ошибкой).

Причина: два бокса одной площади, поставленные друг на друга (общая грань, вершины свариваются), дают у каждого ребра общей грани по 4 грани (2 + 2). Такие рёбра не склеиваются (`== 2`), поэтому грани каждого тела теряют связь через это ребро. Тело разваливается на отдельные грани-пары, которые удаляются как «менее 4 треугольников», а остаток открыт.

Воспроизведение (файл `in\face_touch.stl` = box(0..10)^3 + box(z 10..20), 24 треугольника):

```
cad2gdml face_touch.stl --out out --unit mm --allow-default-material
  I_SPLIT   face_touch разбита на 6 связных тел
  W_COMPONENT_TINY (x4)  ... менее 4 треугольников — удалено
  E_MESH_OPEN face_touch_c02: Открытая сетка.
  код 3
cad2gdml face_touch.stl --keep-open ...   -> код 0, "Треугольников: 20" (было 24: потеряно 4)
cad2gdml face_touch.stl --drop-open ...   -> код 3 E_SCENE_EMPTY
cad2gdml face_touch.stl --no-split  ...   -> код 3 E_MESH_NONMANIFOLD ("Уберите --no-split: касающиеся тела разделятся")
стопка из трёх боксов (in2\stack3.stl): 11 кусков, код 3 E_MESH_OPEN
```

Та же сборка до диффа (3fc3128): `face_touch.stl` -> код 0, 24 треугольника, предупреждение W_MESH_NONMANIFOLD. То есть это регрессия на реалистичном входе (детали сборки, поставленные друг на друга с совпадающим контуром). Из трёх режимов ни один не даёт результата без потерь; текст ошибки при `--no-split` отправляет пользователя в режим, который тоже падает.

Что не затронуто: частичное перекрытие граней (`in\face_touch_part.stl`) даёт 2 корректных тела, код 0; касание ребром и точкой (`edge_touch`, `point_touch`, `checker`) даёт 2 тела, код 0, 24 из 24 треугольников.

### V1. Важная. Крупнейший кусок выбирается по числу треугольников, а не по объёму; кристаллом становится не то тело при коде 0

Файл:строка: `src/Cad2Gdml.Core/Scene/RoleAssigner.cs:141` (`tc > bestTc`), `:149` (порог 80 % по треугольникам). Объёмы к этому моменту уже посчитаны (`ProcessMeshes` идёт до `AssignRoles`), но не используются.

Воспроизведение (`in5\crystal.stl` = куб 100 мм (12 треугольников) + сфера радиуса 2 мм (2208 треугольников)):

```
cad2gdml crystal.stl ...  -> код 0
  W_ROLE_GUESS  ... роль кристалла оставлена у крупнейшего (crystal_c01)
отчёт: crystal_c01 | кристалл | NaI | тетра | 0.03 см³ | 4×4×4
       crystal_c02 | прочее   | NaI | бокс  | 1000.00 см³ | 100×100×100
```

Кристаллом назначен шарик 4 мм (0,03 см³), куб 1000 см³ понижен до «прочее». Предупреждение есть, но называет выбранный кусок «крупнейшим», что неверно. Мелкая детализация (резьба, скругления) у любого второго тела в файле даёт тот же эффект.

### V2. Важная. Два разных файла с именами `<имя>_c1`, `<имя>_c2` принимаются за куски одного разбитого файла

Файл:строка: `RoleAssigner.cs:112` (`^(.+)_c(\d+)$` по имени детали без проверки происхождения).

Воспроизведение: `crystal_c1.stl` (куб 100 мм) и `crystal_c2.stl` (сфера) поданы вместе:

```
W_ROLE_GUESS crystal: файл разбит на несколько тел: роль кристалла оставлена у крупнейшего (crystal_c2)
I_ROLE crystal_c1: Other      I_ROLE crystal_c2: Crystal       -> код 0

До диффа два кристалла давали E_ROLE_AMBIG (код 4). Теперь отдельный файл молча понижается по ложной причине «файл разбит». Нужен признак происхождения (исходное имя или файл) вместо разбора имени регуляркой.

### V5. Важная (не регрессия). Внутренняя поверхность полости превращается в сплошное тело

Файл:строка: `Cad2GdmlPipeline.cs` (ветка `vol < 0.0 -> FlipWinding`, строка около 330).

Воспроизведение (`in\cavity.stl` = куб 20 мм + внутренний куб 10 мм с обратной ориентацией, то есть полая деталь):

```

W_MESH_FLIPPED cavity_c02: Объём отрицательный — ориентация инвертирована.   -> код 0, Объёмов: 3

Полость получает положительный объём и становится вторым сплошным телом внутри первого (перекрытие, G4_AIR по умолчанию). Для точной вложенности (`nested.stl`, обе поверхности наружу) результат тот же. Поведение идентично версии 3fc3128 (проверено), так что регрессии нет, но по пункту (а) знак объёма куска не различает «вывернутое тело» и «поверхность полости», а текст предупреждения вводит в заблуждение.
