## Важное

**1. HoleFiller: неверное разбиение контура при повторе вершины даёт ложную крышку.**
`src/Cad2Gdml.Core/Meshes/HoleFiller.cs:180-198`, цитата: `int len1 = repeatPos + 1; ... for (int i = 0; i <= repeatPos; i++) l1.Add(verts[i]);`.
Замкнутым циклом является `verts[repeatPos..end]` (его берёт `l2`). Префикс `verts[0..repeatPos]` — это незамкнутый «хвост»: ребра `verts[repeatPos]→verts[0]` среди граничных нет. Но он тоже добавляется в `rawLoops`, если его длина >= 3.
Сценарий (воспроизведён): вершины 0..4 и P=5, индексы `{5,2,4, 0,1,5, 0,5,3}`. Граница состоит из пинч-вершины P: контур 0→1→P→3→0 и контур P→2→4→P.
Результат пробы: `filled=2 skipped=0`, добавлены треугольники `cap 0,5,1` (обратная копия существующего треугольника 0,1,5, то есть складка нулевой толщины) и `cap 5,4,2`. Настоящий контур 0-1-P-3 остаётся открытым.
Итоговая сетка из `Fill` некорректна, а счётчик `filled` завышен. В пайплайне (`Cad2GdmlPipeline.cs:371-373`) результат отбрасывается проверкой `OpenEdges==0`, поэтому порча не доходит до GDML. Но заявленное разбиение «в точке повтора» фактически не работает, а публичный метод возвращает заведомо неверную сетку.
Тестов на пинч-контур нет (`Checks2h.cs` проверяет только бокс).

**2. StepImporter: `WaitForExit(300000)` не дожидается асинхронного чтения stdout/stderr.**
`src/Cad2Gdml.Core/Import/StepImporter.cs:124`. Версия `WaitForExit(int)` возвращает true до получения EOF от `OutputDataReceived`/`ErrorDataReceived`; для сброса буферов нужен повторный вызов `WaitForExit()` без аргумента.
Сценарий: Python падает с кодом 2/3/4 и печатает JSON-ошибку. `sbOut` читается (строка 140) раньше, чем доставлена последняя строка, и ошибка превращается в `E_STEP_INTERNAL` с хвостом stderr вместо кода и сообщения скрипта. Аналогично теряются строки «skipped». Гонка плавающая, статус «не подтверждено запуском», но следует из документированного поведения API.

**3. StepImporter: предупреждения собираются, но на ошибке не показываются, а на успехе сейчас не появляются.**
`StepImporter.cs:178` и `:186`; `Cad2GdmlPipeline.cs:198-216`.
(а) При ошибке `AddSkippedWarnings` вызывается (178), но пайплайн возвращается раньше чтения `LastWarnings` (`parts == null`), и данные теряются. Это мёртвый код.
(б) Скрипт `tools/step_export.py` не печатает слово «skipped» нигде (grep по файлу: 0 вхождений). На успешной ветке `AddSkippedWarnings` ничего не найдёт, пока скрипт не изменят. Из-за этого пропуск тела (`tr <= 0 ... continue`, `step_export.py:88-91`) остаётся молчаливым, и пользователь не узнаёт, что деталь выпала.

**4. SceneViewerForm: суффикс «(2)» создаёт иллюзию независимых строк, а логика работает по имени.**
`src/Cad2Gdml.App/SceneViewerForm.cs:209-213` (подпись) против `:422-433` (`_rowNames[i]` как ключ).
Сценарий: две детали с одинаковым именем (разные STL в каталоге). Пользователь снимает галку только со второй строки «X (2)»: в `Excluded` попадает «X», и исключаются обе детали. Материалы двух строк с разным выбором дают два правила `=X`, применится первое. Подсветка и скрытие (`:359`, `:385`) тоже по имени.
Если реальная деталь называется «X (2)», подпись дублируется.

## Мелочи

**5. HoleFiller: замкнутые пути, не прошедшие проверку, и переполнение `maxLoopEdges` не попадают в `skipped`.**
`HoleFiller.cs:169-173` (`if (!closed || !valid) continue;`). До правки в таких случаях был `skipped++`. Теперь счётчик занижен.
Сейчас пайплайн использует только `filled` (`Cad2GdmlPipeline.cs:367-381`), поэтому на выход это не влияет.

**6. HoleFiller: проверка названа «выпуклостью», а проверяет звёздность относительно центроида вершин.**
`HoleFiller.cs:217-261`. Вогнутые контуры с центроидом вне ядра теперь молча пропускаются (раньше заполнялись веером, возможно, с перекрытием). Тестов на вогнутый контур нет.
Порог `LengthSq() <= 1e-30` (`:252`) абсолютный и зависит от единиц сетки. Для `k == 3` проверки нет, вырожденный коллинеарный треугольник пройдёт (`:283-289`).

**7. StepImporter: `LastWarnings` — общий статический список, читается без блокировки.**
`StepImporter.cs:14-20`, чтение в `Cad2GdmlPipeline.cs:211-216`. Запись под `WarnLock`, чтение нет. Два одновременных конвертирования (GUI-поток плюс CLI-сессия или два фоновых потока) дают `Clear()` во время обхода и `ArgumentOutOfRangeException`/смешение предупреждений разных файлов. Не подтверждено запуском. Исключение поймано в `catch` только вокруг `Load`, а не вокруг цикла чтения.

**8. StepImporter: процесс не освобождается и не ждётся после `Kill()`.**
`StepImporter.cs:98-132`. `Process` нигде не `Dispose`, после `Kill()` нет `WaitForExit()`, дочерние процессы Python не убиваются. В `finally` (`:234-239`) удаление temp-каталога может не пройти, пока процесс ещё держит файлы, и ошибка гасится, поэтому каталог утекает. Сценарий: таймаут 5 минут на большом STEP.

**9. StepImporter: разбор сообщения об ошибке.**
`StepImporter.cs:159` — шаблон `"message"\s*:\s*"([^"]*)"` обрывается на первом `\"` внутри JSON-строки (`repr(e)` с двойными кавычками, `step_export.py:109`), то есть сообщение усекается. `Regex.Unescape` (`:167`) — не JSON-декодер: последовательности вроде `\d` бросают исключение (поймано, остаётся сырой текст), а `\x..`/`\0` трактуются по правилам regex.

**10. SketchBuilder.ChainSegs: использованные сегменты остаются в списках ячеек.**
`SketchBuilder.cs:~665-850`. Каждый шаг роста пересматривает все записи ячейки, включая уже `used`. На сценарии с очень большим числом сегментов в одной ячейке (вырожденный «ёж» из десятков тысяч совпадающих концов) выходит O(n^2). На обычных контурах O(n). Не подтверждено замером.
Порядок выбора ветки в узле ветвления теперь зависит от обхода ячеек (раньше — от минимального индекса сегмента). Результат цепочек в узлах степени >= 3 может отличаться от прежнего. Тестов на такой случай нет.
Ключ ячейки `(long)Math.Floor(x / 1e-4)` не защищён от NaN/Inf: приведение неопределено, но исключения нет, сегмент просто не сшивается.

**11. scripts/build_loop.py:163 — значение по умолчанию `gen_code.py` относительное.**
Без `GEN_CODE_PY` запуск ищет файл в текущем каталоге и падает с `rc != 0` и кодом выхода 10, без подсказки о переменной окружения. Сообщение должно называть `GEN_CODE_PY`.

**12. MaterialLibrary: корпус, свинец и медь теперь приоритетнее кристалла.**
`MaterialLibrary.cs:95-105`. Поведение соответствует комментарию и тесту `material_rules_order`. Побочный эффект: имя вида «NaI crystal in Pb shell» или «LaBr3 case» получает Al/Pb, а не кристалл. Для «Cu»/«Pb» как отдельного слова в имени кристалла (маркировка партии) возможно ложное срабатывание. Не подтверждено на реальных данных.
