## Важные (M)

**M1. Fmt округляет до 4 знаков: плотность и доли материалов искажаются (GdmlWriter.cs:208, применение :454, :462).**
`Math.Round(v, 4)` стоит перед форматом `0.######`; в v0.1 было 6. Воспроизведение: materials.json с
`{"name":"Aer","density":0.00005,"fractions":[["Si",0.99997],["O",0.00003]]}` -> GDML `<D value="0">`, `<fraction n="1" ref="Si"/>`, `<fraction n="0" ref="O"/>`, код 0 OK.
Также `density 1.23456` -> `1.2346`, доли `0.123456/0.876544` -> `0.1235/0.8765`; `0.001205` (газ) -> `0.0012` (-0.4 %).
Плотность 0 в Geant4 недопустима. Тихая порча без предупреждения. Для координат 0.1 мкм допустимо, для D и fraction -- нет.
Мера: для D и fraction формат "R"/6 знаков; 4 знака оставить только для длин.

**M2. Ссылки в fraction пишутся как набрано пользователем, а определения -- каноническими именами (GdmlWriter.cs:460-463).**
Воспроизведение: custom A `fractions [["nai",0.5],["Si",0.25],["SI",0.25]]` -> код 0, в GDML `<fraction ref="nai"/>` при `<material name="NaI">`,
`<fraction ref="SI"/>` при `<element name="Si">`; для `["fe",1]` создаётся `<element name="fe">`. Имена GDML регистрозависимы -> битая ссылка,
Geant4 не загрузит файл, а конвертер говорит OK. Библиотека (OrdinalIgnoreCase) и таблицы ElZ/ElA регистр не различают, писатель -- различает.
Мера: канонизировать sym через lib.Find(...).Name и каноническое имя элемента.

**M3. Заявленные коды выхода 5 вместо 9 фактически не достигаются для ошибок GdmlWriter (Cad2GdmlPipeline.cs:538-547, 103-107).**
GdmlWriter бросает `InvalidDataException("E_MAT_CYCLE: ...")`, `E_ELEMENT_UNKNOWN`, `E_MAT_UNKNOWN`, но WriteOutputs ловит их и безусловно добавляет `E_FORMAT`
(MapExceptionCode здесь не используется). Воспроизведение: custom A->B->A -> `код 2 E_FORMAT -- Не удалось записать результат: E_MAT_CYCLE: A`;
fraction `["Xx",1]` -> `код 2 E_FORMAT ... E_ELEMENT_UNKNOWN: Xx`. Ожидается 5 (DeriveExitCode уже умеет E_MAT*/E_ELEMENT_UNKNOWN). Ошибка обнаруживается только после рендера PNG.
Мера: в catch использовать MapExceptionCode(ex); валидацию ссылок и циклов перенести в LoadJson (E_MAT_*).

**M4. Запись выходных не атомарна; временные файлы остаются (Cad2GdmlPipeline.cs:556-562, 538-547, 103-107).**
(a) Старые файлы удаляются ДО переноса новых. Воспроизведение: прогон, затем `chmod` read-only на `crystal.png`, повторный прогон -> код 2 `Отказано в доступе`,
в папке остались только `crystal.png`, `crystal.report.txt`: прежний валидный `crystal.gdml` удалён, нового нет.
(b) Фильтр catch не содержит `ExternalException` (GDI+ Save). Воспроизведение: каталог `out\crystal.png.tmp` заранее -> код 2 `В GDI+ возникла ошибка общего вида`,
в out остаются `crystal.gdml.tmp` и `crystal.png.tmp` (CleanupTemp не вызван, внешний catch в Run не чистит).
(c) Если PNG-путь занят каталогом: GDML заменён новым, report удалён -- набор частично новый.
Мера: `catch (Exception)` + CleanupTemp в finally; переносить через `File.Replace`/Move с overwrite (net48: File.Replace) без предварительного Delete.

**M5. 3MF: экспоненциальный рост меша по компонентам -- лимит MaxTotalTriangles проверяется после построения (ThreeMfImporter.cs:489, 222).**
`ResolveLocal` кэширует, но `local.Append(childTransformed)` копирует меш ребёнка в каждого родителя: объект k = 2 компонента объекта k-1 -> 2^k копий.
Глубина ограничена 32, лимит 50M треугольников проверяется в Load только после полной сборки. Файл 4.3-4.7 КБ (куб + цепочка из N удвоений):
N=12 0.1 с, N=18 0.5 с, N=20 2.1 с, N=22 8.8 с (x4 на 2 уровня); N=24..32 -> десятки миллионов...миллиарды треугольников, OOM/минуты, код 9 или падение.
Мера: считать число треугольников/вершин по графу без материализации (с кэшированным счётчиком) и отказывать до Append.
DTD отклоняется (код 2, E_FORMAT "3MF: XML error: model" -- без слова DTD), цикл (`component cycle`) и глубина 44 (`depth exceeded`) -- код 2, корректно.

**M6. MainForm: при ошибке остаются устаревшие картинка и отчёт прошлого успешного прогона (MainForm.cs:361-364, 328-331).**
Удалены `_picSketch.Image = null` и `RenderReport(result)` в ветке сбоя; `_txtReport` нигде не очищается перед запуском (только присваивание на :431 при успехе).
После успешной конвертации и последующего сбоя пользователь видит красную строку и рядом старый эскиз/старый SHA/старые детали. Диагностики (предупреждения, другие ошибки) при сбое не показываются совсем.
Красная строка: `MainErrorId + " -- " + MainErrorMessage` (:361) -- без кода выхода; при `MainErrorId == null` (ExitCode 9) строка будет " -- ". Проверено чтением кода (окно не запускалось).
Мера: очищать эскиз и отчёт при старте, при сбое вызывать RenderReport (там уже есть блок диагностики), добавить код выхода и запасное "E_UNKNOWN".

**M7. `stl_default`: DefaultFromFile=true выставляется при любом значении ключа (MaterialLibrary.cs:206-210).**
Отсутствуют фигурные скобки у `if (ds != null)`: вторая строка `lib.DefaultFromFile = true;` выполняется всегда. Воспроизведение: `"stl_default": null` (или число) ->
остальные детали молча получают встроенный G4_AIR без `--allow-default-material`, код 0 (с W_MAT_DEFAULT). Ожидается E_MAT_UNASSIGNED (5).

**M8. MainForm: единицы для смешанных входов (MainForm.cs:316-321; ThreeMfImporter.cs unitOverride).**
Если не все входы .3mf, ComboBox-значение передаётся и 3MF; override > 0 перебивает unit из файла. Подпись "для 3MF: из файла" (:85) в этом режиме неверна: STL(мм)+3MF(дюймы) при выборе "мм" даст 3MF в 25.4 раза меньше без предупреждения.
CLI ведёт себя так же при `--unit`, но в GUI смешанный ввод всегда имеет значение из ComboBox. Чисто-3MF режим (unit=0 -> из файла) работает; явный выбор пользователя в нём игнорируется.
Мера: диагностика W_UNIT_OVERRIDE при расхождении или раздельные единицы по формату.

**M9. W_SOURCE_BEHIND -- ложные срабатывания (Cad2GdmlPipeline.cs:371-384).**
Критерий: центр bbox источника/контейнера `cz < 0`. Воспроизведение: кристалл Ø40x50 и стакан-контейнер `beaker` (труба r25..40, z -10..60), охватывающий кристалл
(геометрия Маринелли/колодца) -> `W_SOURCE_BEHIND [Warning] beaker`, хотя --front верен. Образец сбоку от кристалла (центр z в теле кристалла) тоже помечается. Предупреждение лишь Warning (код 0), но шумит на штатной геометрии.
Корректнее: проверять, что весь bbox источника за плоскостью торца (max Z < 0), либо игнорировать охватывающие контейнеры.
